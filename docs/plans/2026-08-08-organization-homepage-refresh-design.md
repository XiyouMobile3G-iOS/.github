# 组织首页极简美化设计

## 目标

在不增加栏目和图片素材的前提下，美化 `XiyouMobile3G-iOS` 的 GitHub 组织首页。首页优先服务准备加入实验室的 iOS 学习者，同时让招聘方、合作方和学校能够快速理解组织定位与代表性项目。

## 设计方向

采用 Apple 风格的极简黑白排版：克制、清晰、重视内容层级和留白。设计不依赖横幅、插画、Emoji、动态效果或复杂 HTML，以保证 GitHub 深浅色模式、移动端和长期维护的稳定性。

## 信息架构

保留现有内容区域和顺序：

1. 品牌区
2. 关于我们
3. 精选项目
4. 知识沉淀
5. 关注方向
6. 一起构建
7. 页脚标语

不新增学习路径、成员展示、成果数据或其他栏目。

## 视觉层级

- 品牌区居中，使用现有组织头像、组织名称、精简标语和三个页内导航链接。
- 正文全部左对齐，使用标准 Markdown 二级标题。
- 品牌区与正文之间使用单条分隔线，不堆叠装饰元素。
- 精选项目继续使用两列表格，统一项目简介的语气与长度。
- 关注方向继续使用行内代码样式作为低调标签，不引入远端徽章图片。
- 页脚保留英文标语，拆成两句以形成简洁节奏。

## 内容语气

- 面向访客的主要内容使用简洁、自然的中文。
- 首屏标语聚焦 Apple 平台、工程实践和可交付产品。
- 关于我们保留两段短文：第一段说明资源范围，第二段说明学习和实践方式。
- 链接文字使用明确动作，如“浏览项目”“查看知识库”“参与共建”。
- 不夸大规模、成果或活跃度，不加入无法验证的数据。

## 可访问性与兼容性

- 组织头像保留准确的替代文本。
- 不使用依赖固定颜色的文字或背景，避免深色模式对比度问题。
- 不使用宽幅图片或双列卡片，避免移动端横向滚动。
- 仅使用 GitHub 支持的 Markdown 与简单 HTML 对齐属性。
- 链接名称应能独立表达目标，不使用含糊的“点击这里”。

## 文件与数据流

- 修改 `profile/README.md`，它仍是组织首页内容的唯一事实来源。
- 更新 `memory.md`，记录已确定的极简视觉方向，并移除“美化方向尚未选定”的待确认项。
- 不新增图片、脚本、依赖或自动生成文件。

## 验证

- 检查 Markdown 标题层级、表格、HTML 标签和页内锚点。
- 检查所有仓库链接、组织链接和图片地址。
- 使用 `git diff HEAD --check` 检查空白错误。
- 确认最终差异仅包含 `profile/README.md`、`memory.md` 和设计/计划文档。
- 确认 README 在窄屏下不依赖固定宽度布局。
